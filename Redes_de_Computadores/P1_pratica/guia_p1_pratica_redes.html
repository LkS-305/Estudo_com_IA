0 Como usar este guia e o que levar escrito

A prova é uma configuração completa no Packet Tracer, parecida com os Labs 6 e 7. O professor confere de dois jeitos: pinga de uma VLAN para outra (tudo tem de responder) e lê o log de comandos. Este guia reproduz exatamente a forma como ele configurou nos gabaritos (lab7/Exercicio - 2026-11-09-gabarito.pkt e lab6_ospf/OSPF-2026-10-19-gabarito.pkt): os mesmos comandos, as mesmas abreviações, a mesma ordem.

Ordem sugerida das folhas

  1. Folha-resumo (última seção). Se só der tempo de copiar uma coisa, é ela.
  2. Como o professor digita (seção 2): as abreviações e os comandos dele.
  3. Provas práticas de 2025 (A e B) (seção P) — a prova real do ano passado: VLANs + EtherChannel + OSPF área 0, enlace serial e um roteador de parceiros com rota estática.
  4. Gabarito do Lab 7 passo a passo — é o formato mais parecido com o que ele anunciou (VLANs + EtherChannel + STP + OSPF por área).
  5. Gabarito do Lab 6 — OSPF em várias áreas com roteadores estáticos.
  6. Tabelas: máscaras, blocos /30, códigos da tabela de rotas, matriz de ping e diagnóstico.
  7. Folhas em branco com as tabelas-modelo (inventário, endereçamento, plano por roteador e por switch, matriz de ping).

Etiquetas: jeito do professor = está no gabarito · fora do gabarito = não aparece nos logs dele (só reserva) · ✍ copiar = essencial. Em «amarelo» nos comandos estão os valores que mudam na prova.

1 Regras desta prova ✍ copiar

⛔ Tudo pela CLI

  • Roteador e switch: só a aba CLI. Nunca a aba Config.
  • O .pkt grava cada comando com hora e equipamento — é o log que o professor lê. Erro de digitação fica no log; não tem problema (o gabarito dele tem vários: e na, wqr, enas). Corrija com no … e siga.
  • Hosts: no gabarito, o professor configurou PCs e laptops em Desktop → IP Configuration; essa janela não entra no log. Se ele exigir linha de comando também nos hosts, o equivalente é Desktop → Command Prompt: ipconfig «IP» «máscara» «gateway». Pergunte no início da prova.

✅ Critério: ping entre VLANs

  • Ele vai pingar de hosts de uma VLAN para hosts de outra. Todos têm de responder.
  • Um ping só funciona com ida e volta: cada roteador do caminho precisa de rota para o destino e para a origem.
  • Antes de entregar, faça a matriz de ping completa.
  • No fim: wr em todos os roteadores e switches e Ctrl+S no arquivo.

⚠ Redistribuição: o que o professor fez

No Lab 7 as notas diziam "Não use redistribuição" e "OSPF Area 3" para o prédio B, mas no gabarito o professor pôs no R2 redistribute connected subnets (as VLANs 30/40 viram O E2 [110/20]). Nos dois exercícios do Lab 6 ele também usou redistribute connected subnets para as LANs. Este guia segue o gabarito. A forma "como a nota pede" (network … area 3) fica numa caixa separada, caso ele cobre o texto da nota.

2b Cada comando explicado — o que faz e onde é digitado ✍ copiar

Na CLI, o prompt diz onde você está, e cada comando só funciona no modo certo. Primeiro o mapa dos modos; depois a configuração de equipamentos reais dos gabaritos, linha por linha; no fim, um dicionário de todos os comandos.

Os modos da CLI (o prompt)

Router>                  modo USUÁRIO         só consulta básica (ping). Entrada ao abrir a aba CLI.
   │ ena
Router#                  modo PRIVILEGIADO    todos os sh …, ping, wr, reload.
   │ conf t
Router(config)#          configuração GLOBAL  vale para o equipamento inteiro: hostname, ip route,
   │                                          spanning-tree, e a porta de entrada dos submodos:
   ├── int fa0/0     →  Router(config-if)#        configura UMA porta: ip add, no shut, switchport…
   ├── int range …   →  Router(config-if-range)#  configura VÁRIAS portas de uma vez
   └── router ospf 1 →  Router(config-router)#    configura o OSPF: network, redistribute

exit  = sobe um nível (config-if → config → #)        end = volta direto para o #
De dentro de um submodo dá para ir direto a outro: estando em (config-if)#, digitar int fa0/1 troca de porta,
e router ospf 1 entra no OSPF. Comandos globais (ip route, hostname) também são aceitos de dentro de um submodo.

"Onde": R = roteador, S = switch, H = host (PC/laptop). O nome antes do >/# é o hostname: Switch e Router são o padrão; depois de hostname router0 o prompt vira router0#.

F2 Desenhar e contar as redes

Redesenhe no papel: caixas para roteadores, traços para links, a porta escrita nas duas pontas. Depois conte as redes IP.

2.1 Regras de contagem ✍ copiar

  1. Cada interface de roteador está numa rede diferente.
  2. Cada VLAN é uma rede. A VLAN é definida pela porta do switch, não pelo IP.
  3. Switch sem VLAN não separa nada: tudo pendurado nele é uma rede só (prédio C do Lab 7, LANs do Lab 6).
  4. Enlace roteador–roteador = uma rede /30.
  5. Trunk e EtherChannel não criam rede: só transportam as VLANs.

★ Matriz de ping entre VLANs (o teste do professor) ✍ copiar

Teste na ordem abaixo: o primeiro degrau que falha diz onde está o defeito.

DegrauPing de… para…Se falhar, o problema está em
1Host → seu gatewayIP/máscara do host, porta do switch na VLAN errada, porta do roteador na VLAN errada, falta no shut, trunk/canal no caminho.
2Host → host da mesma VLAN em outro switchTrunk (VLAN fora do allowed, VLAN inexistente num switch de passagem), EtherChannel.
3Host → host de outra VLAN do mesmo roteadorGateway de um dos dois hosts.
4Host → host de outro prédio/áreaOSPF: vizinho não FULL, network faltando, área errada, LAN não redistribuída.
5Host → LAN atrás de roteador estáticoip route, redistribute static subnets, rota padrão do estático (caminho de volta).

Como ler o resultado

  • Reply from … = ok.
  • 1º ping com 1–2 Request timed out e depois respostas = normal (ARP). Repita.
  • Request timed out sempre = a ida ou a volta se perdeu.
  • Destination host unreachable = algum roteador (ou o host) sem rota/gateway.

Por que um ping entre VLANs falha

  1. Host sem gateway ou gateway errado.
  2. Porta do switch do host na VLAN errada.
  3. Porta do switch que vai ao roteador na VLAN errada.
  4. VLAN inexistente num switch que só a transporta.
  5. Trunk sem a VLAN em allowed vlan.
  6. Interface do roteador sem no shut ou com IP de outra rede.
  7. Rede faltando no OSPF.
  8. Roteador estático sem rota de volta / sem redistribute static subnets.

Regras

Roteador e switch só pela aba CLI. Hosts: IP Configuration (como ele fez) ou ipconfig no Command Prompt (se exigir). Teste: ping entre VLANs, tudo responde. Fim: wr em todos + Ctrl+S.

Papel

  1. Ler as notas (áreas, "root", "estático", "redistribuição").
  2. Portas de cada cabo (mouse sobre o cabo).
  3. Contar redes: 1 por interface de roteador, 1 por VLAN, /30 por R–R.
  4. LAN /24 gw .1, hosts .2+; R–R /30 (.1/.2, .5/.6, .9/.10…).
  5. Cada rede: área do network ou redistribute; estáticos: default + ip route + redistribute static.
  6. Switches: access/trunk/canal; root primary no switch pedido.
  7. Roteador vermelho (parceiro): não tocar. No vizinho: IP imposto (interface certa!) + ip route + redistribute static.

Tabelas
